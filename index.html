The Scalability Protocols

Patterns for programs that need to talk.

nanomsg is a family of lightweight messaging protocols for building distributed systems. Start with the communication pattern you need; choose the implementation that fits your language.

Protocol first

A small vocabulary for distributed systems.

Each protocol describes how peers exchange messages. Implementations share this model, letting you make a deliberate choice about language, API, and lifecycle without losing sight of the topology.

01

PAIR

Direct one-to-one communication between two peers.

 02

PUB / SUB

Publish messages to every interested subscriber.

 03

REQ / REP

Route requests to services and receive replies.

 04

PUSH / PULL

Distribute work and aggregate messages.

 05

BUS

Exchange messages in a simple many-to-many mesh.

 06

SURVEYOR / RESPONDENT

Ask many peers a question and collect their answers.

Preferred for C

NNG

A modern C implementation with an updated API, broad transport support, and compatibility help for existing nanomsg applications.

Preferred pure Go implementation

mangos

A native Go implementation of the protocol family, built for Go applications rather than as a wrapper around a C library.

Legacy C API

libnanomsg

The original C implementation. It remains available for existing applications and the language bindings built around its stable API.

Start with libnanomsg →

Preferred Rust binding

nng-rs

A safe, idiomatic Rust wrapper for NNG. It is independently maintained, with its own release lifecycle.

Start with nng-rs →

Preferred Python binding

pynng

Python bindings for NNG with synchronous, asyncio, and Trio-friendly APIs. It is independently maintained.
